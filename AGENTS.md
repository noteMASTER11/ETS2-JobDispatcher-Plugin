# Правила работы над Job Dispatcher SP

Для изменений кода и проверки архитектуры применяй
[ub-mode](.agents/skills/ub-mode/SKILL.md). Сначала прочитай этот файл.
Зафиксированная версия и источник записаны в
[UPSTREAM.json](.agents/skills/ub-mode/UPSTREAM.json).

Проверяй только заказанный объём работы. Запрос на аудит означает отчёт с
доказательствами и план изменений; сам по себе он не требует переписывать DLL.
Сохраняй существующие незакоммиченные изменения. Выпуск, изменение релиза или
тега выполняй только по отдельному указанию пользователя; версии инкрементальные.

## Измерения ub-mode

- Crapper, Dryer и Mutator в зафиксированных версиях поддерживают Python,
  но не C++. Не объявляй их пустой отчёт по `src/` успешной проверкой DLL.
- Разделяй метрики Python-подготовщика, C++-сложность и результаты тестов.
  Проверка на искусственном ABI не подтверждает правильность вызовов ETS2.
- Для mutation testing используй отдельную копию исходников. Если тест получает
  корень через `__file__.resolve()`, проверь, что он действительно импортирует
  изменённый файл рабочего каталога Mutator, а не оригинал через ссылку.
- Сохраняй версии инструментов, область измерения и исходные результаты.

## Игровые проверки

Пользователь разрешил автоматические запуски игры для тестов.
Используй отдельный **локальный** профиль с копией сохранения и отдельные данные
плагина. Один `-homedir` не изолирует Steam Cloud.

Перед загрузкой мира проверь в журнале `Profile type: PC_local` и путь сохранения
`/home/profiles/...` внутри тестового каталога на D:. Не загружай облачный профиль
для автоматического теста. Проверь наличие всех активных модов до входа в мир.
Тест не должен создавать или принимать заказ, если проверяется только превью.

Храни проекты, инструменты, отчёты, кэши и временные файлы под `D:\ChatGPT`.
Задавай TEMP/TMP и кэши только для запускаемого процесса; не меняй общесистемные
настройки. Не включай сохранения игры, учётные данные и игровые ресурсы в Git.
