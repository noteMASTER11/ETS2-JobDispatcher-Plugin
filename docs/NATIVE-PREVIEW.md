# Штатное превью ETS2

Текущая рабочая сборка использует `src/native_preview.cpp`, игровой
`ui_vehicle_preview` и ресурсы загруженного мира. Самостоятельный DX11-рендер
из `preview.cpp` удалён из сборки. Вызов подготовщика выбранной модели удалён
из фонового потока и из API запуска внешних процессов.

## Поддерживаемая сборка

ETS2 1.61.1.9 Windows x64 DX11, SHA-256 исполняемого файла:
`b70c2357cc56eb5834ee47fea3c60b2f2d4591383ff2ac479cfd3cd254301b8c`.
Диспетчер проверяет полный хеш до обращения к внутренним функциям; мост также
проверяет таблицу виртуальных методов и прологи загрузчика и DX11-функции.
Публичный Telemetry SDK не содержит API создания произвольного 3D-превью.
Внутренние привязки требуют повторной проверки после обновления ETS2.

## Путь от выбора до картинки

1. GUI помещает в очередь последний выбор груза, прицепа и отправителя.
   Выбор выдерживается 100 мс; промежуточные значения не создают модели.
2. В callback SDK создаётся частное окно из игрового
   `/ui/layout/vehicle_preview_widget.sii`, элемент ID 1. Его обработчик — null.
   Применяется конфигурация камеры из карточки заказа:
   `/def/job_company_trailer_preview.sii`. Окно инициализирует связи дочерних
   элементов, но не регистрируется в глобальном менеджере игровых меню.
3. Прототип берётся из живого каталога прицепов. Клону назначаются груз,
   количество, рассчитанное игрой для этого кузова, и окраска отправителя.
   Виджет получает клон и создаёт свою копию. Исходный клон освобождается.
   Заказ, физический прицеп и маршрут GPS на этом этапе не создаются.
4. Обновляется базовый объект модели, без обработчика глобального мышиного ввода
   UI. Родной метод рендера формирует игровую сцену и цель 1024 × 640.
   Загрузка ресурсов остаётся асинхронной и выполняется самой игрой.
5. После следующего callback из реестра цели берётся texture handle. Через
   texture pool и DX11 image pool определяется изображение, для которого
   создаётся COM ShaderResourceView штатной функцией игры. Оверлей показывает
   текстуру; чтения DDS, преобразования PIM и копирования пикселей на CPU нет.
6. Смена получателя и переключение способа принятия заказа не меняют внешность
   и не создают новую сцену. Вращение и масштаб изменяют собственный клон
   конфигурации камеры и перерисовывают ту же цель. Общая конфигурация игры
   и камера грузовика не изменяются.

Игровые объекты создаются и освобождаются в callback игры. GUI удерживает свою
COM-ссылку до завершения кадра. При закрытии окна, паузе, смене мира или устройства
ресурсы освобождаются. Пауза освобождает сцену перед выгрузкой мира.

## Проверки и ограничения

Статически сопоставлены методы, поля и DX11-пулы с конкретным EXE. Тест
`native-preview-frame-and-lifetime` выполняет код моста на искусственном игровом
ABI и настоящем DX11 WARP: очередь выбора, пропуск промежуточного выбора,
окраска отправителя, смена получателя без пересоздания, повторное использование
цели, смена мира и время жизни COM-ссылок. Остальные тесты проверяют маршруты,
ввод, локализации и установочный процесс.

После разрешения пользователя выполнена проверка в ETS2 на отдельном локальном
профиле `JDPreviewTest`, с 18 активными модами, включая ProMods. Подтверждены
материалы, окраска отправителя, изменение превью через «Удиви меня», закрытие и
повторное открытие. Получены `total_ms` 359, 343 и 297 мс. Это отдельные замеры,
а не гарантия времени на другом компьютере. Искусственный ABI не заменяет
игровую проверку. Замеры прежнего Python-подготовщика к ним не относятся.

## Исправление падения при открытии окна, 28.10.2026

Отчёт пользователя от 17:46:21 зафиксировал ACCESS_VIOLATION в игровой функции
`0x1400f2f60`, инструкция `0x1400f2f83`, при назначении `config_path`.
В установленной DLL адрес возврата `RVA 0x3c81f` соответствует этому вызову.
Вместо объекта `string_t` по смещению `widget + 0x118` передавался его член
`char*` по смещению `+0x120`. Функция принимала пару length/capacity
`0x000000200000001e` за адрес буфера и пыталась записать по нему нулевой байт.

Исправлен адрес объекта. Перед назначением проверяются vtable строки, буфер,
длина, ёмкость и завершающий ноль; после вызова проверяется результат.
Тестовый ABI теперь воспроизводит настоящий заголовок строки из конструктора
`0x140ff2c00`. С прежним вызовом тест падает; с исправлением проходит и отдельно
проверяет отклонение ошибочного адреса `+0x120`. Скрипт проверки ABI сопоставляет
смещения строки с машинными инструкциями конструктора. Успешное открытие окна
после исправления также подтверждено в указанном локальном игровом профиле.
