# Как TruckersMP выводит превью

Проверка выполнена статически, без запуска ETS2 или загрузки DLL в процесс.
Исследована установленная `core_ets2mp.dll`, SHA-256
`5282bff1e462dd7b3ca3583e7657a0c7997e0ab344eff44d9d161ffbb75847ac`.
Существующая база Ghidra использована в режиме чтения, без повторного полного
анализа. Адреса ниже — предпочтительные VA этой DLL; они не переносятся в ETS2.

## Цепочка

1. Обработчики выбора `0x1800f5110` и `0x1800f5190` получают выбранный прототип
   прицепа через `0x1800fa130` из модели данных диспетчера. Прототип клонируется
   виртуальным методом. При необходимости присваивается определение прицепа.
2. Выбранный груз берётся из игрового каталога. Вызываются нативные функции игры
   для расчёта загрузки и назначения груза клону прицепа. В этой ветке нет
   ConverterPIX, чтения PIM или извлечения DDS во временные файлы.
3. `0x1800fe2f0` создаёт компонент игрового интерфейса и загружает
   `/ui/truckersmp/trailer_view.sii`. При ошибке пишет сообщение
   `[TrailerPreview] Cannot load the trailer preview!`.
4. `0x1800fe150` находит элементы игрового UI по ID 10002 и 10003. Виджету 10003
   назначается подготовленный прицеп и токен окраски компании через виртуальный
   метод со смещением 0x1a0. Таким образом, используется игровой объект и игровой
   виджет, а не отдельно отрисованная PNG-картинка груза.
5. Адаптер `0x1801c3230` создаёт нативный UI и постоянную цель рендера.
   `0x1801c36d0` обновляет и рисует игровой UI в эту цель, без её пересоздания
   для каждого кадра. `0x1801c3410` получает соответствующий графический ресурс
   и выводит его внутри оверлея TruckersMP. `0x1801c3110` освобождает объекты.

Это подтверждает архитектуру штатного превью. Скорость конкретного вызова и
поведение при смене профиля в ходе этой статической проверки не измерялись.

## Перенос на текущую ETS2

Адреса TruckersMP относятся к другой сборке игры. Они заново сопоставлены с
установленной ETS2 1.61.1.9, а не сдвинуты на общую константу. В рабочую DLL
включён `native_preview.cpp`: частный штатный виджет, игровой клон прицепа с
грузом и окраской, игровая цель рендера, DX11 SRV для оверлея. Прежний конвертер
выбранной модели из runtime-пути удалён. Код и ресурсы TruckersMP не копируются.

Используется минимальный игровой layout с обработчиком null. В него назначена
камера карточки заказа. Перечень привязок, владение объектами и ограничения
проверки описаны в [NATIVE-PREVIEW.md](NATIVE-PREVIEW.md).

Старые замеры Python-подготовщика в 7–16 секунд не измеряли игровой GUI.
В пользовательском игровом журнале найдено около 25 секунд между выбором
погрузчика и готовностью прежней модели. Пользователь также сообщает 30–40
секунд ожидания. Они относятся к собственному подготовщику, который новый
путь больше не вызывает. Скорость нового моста внутри ETS2 пока не измерена:
в ходе доработки игра не запускалась.
